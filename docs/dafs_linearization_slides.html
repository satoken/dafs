THE MAIN MESSAGE

ポイントは「4つの置換」が一本のパイプラインになったこと

速度だけを上げたのではなく、確率・候補・復号・証明を同じ疎なsupport上でつないだ。

01

Linear化

LinearPartition / LinearAlign、固定beam、閾値疎行列、LinearNussinov / LinearNeedlemanWunsch。

02

RIBOSUM

pair–pair matchにRIBOSUM85-60を導入。構造・整列・CBPのjoint objectiveを強化。

03

UB / LB + 修飾subgradient

beamをUBと誤解せず、certificate UBとrepair LBを分離。Polyak stepをtrackごとに整合。

04

dynamic CBP

CBPを全列挙せず、ADD・PRICE・PRUNEでworking setを更新。positive reduced costを逃さない。

長さ方向固定閾値・固定beam・固定反復ならO(n)
目的関数RIBOSUMをDD / repair / IPで共有
証明beam searchと厳密relaxationを別トラック
候補dynamic pricingでCBPを必要時だけ追加
Difference from original DAFS: the dual decomposition is preserved; the probability engines, decoders, CBP management, bounds and update tracks are replaced or extended.

03 / CERTIFIED UB + LB

UB / LB：最適値を「下から」と「上から」挟む

DAFSは最大化問題。実行可能解のscoreはLB、制約を緩めた問題の厳密解はUBになる。

1 / 下から押さえる

beam → repair

beamで構造・alignmentの候補を探す。3者が噛み合わなければ、intersection / consensus repairで整合させる。

実行可能解のscorescore ≤ OPT　⇒　LB
良い解が見つかるほど LB は上がる ↑
対象のDAFS問題

本当に知りたい値

OPT

全制約を満たす構造・alignment・CBPの最大score。直接求めるのが難しいので、両側から挟む。

2 / 上から押さえる

relaxation → certificate

制約を外して候補集合を広げた問題を、folding certificateやrow relaxationで厳密に解く。

緩和問題の厳密な最大値OPT ≤ relaxed optimum　⇒　UB
証明が強くなるほど UB は下がる ↓
LBt　≤　OPT　≤　UBt　 この範囲は常に正しい
重要：beamの値をそのままUBとは呼ばない。beam外に、もっと良い解が残っているかもしれないから。beamはLBを探す役割。
gap = UB − LB
gapが0に近いほど、最適値を狭く特定できる。
Polyak step　ηt = α · max(0, D(qt) − LBt) / ||gt||²　　relaxationの目的値と、その同じ問題のsubgradientを対応させる

04 / DYNAMIC CBP

dynamic CBP：必要な列だけを生成し、pricingで漏れを探す

CBP候補を最初から全列挙せず、現在の解とreduced costを見ながらworking setを更新する。

STEP 01

ADD

現在のx / y / zから、整合しそうなCBPを双方向separationで候補化。

STEP 02

PRICE

未追加の候補をreduced costで走査。RIBOSUM項もここに入る。

STEP 03

PRUNE

staleな列をworking setから外し、次の反復を小さく保つ。

STEP 04

RE-SOLVE

DD decoder・LB repair・UB certificateを同じcandidate集合で更新。

RESULT

full problem
へ近づく

positive reduced-cost columnを逃さず、固定support上で列生成を続ける。

STATIC / PRE-ENUMERATION

CBPを先に全部作る

候補数がprofile長に伴って膨らみ、RIBOSUMを入れるほど管理コストも重くなる。

DYNAMIC / WORKING SET

解きながら追加・削除

候補生成とpricingを分け、score・repair・証明を同じ列集合に通す。linear pathのための実装上の要所。

candidate cacheendpoint別に再利用
positive scoreRIBOSUM positive columnを守る
stale pruningworking setをcompactに保つ
same objectiveDD / LB / IPで一貫
