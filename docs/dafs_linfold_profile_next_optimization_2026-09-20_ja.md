# LinearAlifold プロファイル計算の追加高速化（2026-09-20）

## 実装

- `ProfileNearestNeighbor` の3～64行プロファイルでは、列ごとに A/C/G/U/ギャップの行ビットマスクを保持する。6種類の向き付き正規塩基対と両ギャップの件数を popcount で得る。ペア可否と RNAalifold 型共変異スコアに同じ整数件数を使う。2行の既存36クラス表はそのまま、65行以上は従来の逐次走査・有界キャッシュを維持する。
- プロファイルの `N` 状態から伸ばすヘリックスでは、各行のスタックエネルギー値を一度だけ計算する。各長さの和は従来と同じ外側から内側、各行の和も従来と同じ順序で作る。`E` 状態の単発計算および他のパラメータモデルは変更しない。
- 全行ギャップの列がある場合だけ、その列を内部ループ候補の左端走査から飛ばす線形サイズの索引を用意する。正規塩基対が必ず1行以上必要なため、その列は候補にならない。通常の全ギャップ列なし入力では索引を持たない。

いずれもビーム、DD、スコア関数、候補の走査順、丸め位置を変更しない。ビットマスクは固定行数なら配列長に線形のメモリで、ヘリックス用一時領域は行数×最大ヘリックス長、全ギャップ索引は列数に線形である。

## 長配列の確認

固定ビーム100、`max-iter=5`、seed42、refinement0、DD証明設定を固定。2配列の長い合成入力では1024塩基が13.187→13.498秒、2048塩基が30.402→30.471秒であり、高速化を確認できなかった。両長さとも予測SHA-256は完全一致した。

4配列の長い合成入力では512塩基が11.923→11.683秒、1024塩基が32.785→31.785秒。両長さとも予測SHA-256とDD反復数は一致した。4配列1024塩基の最終共通構造予測段階は4.960→4.285秒。これらの合成入力は単発測定であり、線形性の厳密な経験的証明ではない。

## テストと限界

`cmake --build build-arm64 -j2`、`ctest --test-dir build-arm64 --output-on-failure -j2`（17/17）、`git diff --check` が通過。直接テストは2行の全ギャップ列を含む後続候補探索とBPPの一致、3/10/64/65行の向き付きペア件数とペア可否、ヘリックスエネルギーのbitwise一致を確認する。

3～64行の長いプロファイルには改善があるが、2行だけの長い入力での全体速度はほぼ横ばい。現時点で全構成の長配列実行時間が厳密に線形だと主張しない。全ギャップ列による無駄な左端走査は除去したが、行数や最大内部ループ長を配列長とともに増やす場合の計算量は別途評価が必要である。
